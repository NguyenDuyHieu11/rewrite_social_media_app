## RWMutex User Guide — An Operational Algebra

---

### The Numbers (Primitives)

These are the only atoms you work with:

```
R  — one unit of read lock held by one goroutine
W  — one unit of write lock held by one goroutine
0  — the unlocked state (no one holds anything)
```

The mutex at any moment holds exactly one of these states:

```
0          → unlocked
R, RR, RRR → one or more readers (n readers = nR)
W          → exactly one writer
```

---

### Allowed Operations

Think of these like arithmetic operations — each has rules about when it's valid and what it produces.

---

**Operation 1: `RLock()` — add one R**

```
0   + RLock = R
nR  + RLock = (n+1)R     ← valid, readers stack
W   + RLock = BLOCKS      ← waits until W is gone
nR  + (W waiting) + RLock = BLOCKS   ← writer takes priority
```

You may stack as many R's as you want, but only when no W exists or is waiting.

---

**Operation 2: `RUnlock()` — remove one R**

```
nR + RUnlock = (n-1)R
1R + RUnlock = 0
```

Rules:
- You may only `RUnlock` a lock **your goroutine acquired**
- Calling `RUnlock` without a prior `RLock` → **panic**
- `RUnlock` on `0` → **panic**

---

**Operation 3: `Lock()` — acquire W**

```
0  + Lock = W
nR + Lock = BLOCKS until all R's drain, then W
W  + Lock = BLOCKS until W releases, then W
```

Once `Lock()` is called and blocked, it **poisons all future `RLock()` calls** — they block too, even though only R's currently hold the lock. This ensures the writer eventually gets in.

---

**Operation 4: `Unlock()` — release W**

```
W + Unlock = 0
```

Rules:
- Only the goroutine that called `Lock()` may call `Unlock()`
- `Unlock()` without a prior `Lock()` → **panic**
- After `Unlock()`, all blocked `RLock()` and pending `Lock()` calls compete again

---

**Operation 5: `TryLock()` — non-blocking W attempt**

```
0 + TryLock = W,    returns true
nR + TryLock = 0,   returns false  (no blocking, no acquiring)
W  + TryLock = 0,   returns false
```

---

**Operation 6: `TryRLock()` — non-blocking R attempt**

```
0  + TryRLock = R,   returns true
nR + TryRLock = (n+1)R, returns true
W  + TryRLock = 0,   returns false
```

---

### Forbidden Operations (Undefined / Panic / Deadlock)

Like dividing by zero — these are not valid in this system:

---

**1. R → W (upgrade) — DEADLOCK**

```
R + Lock = DEADLOCK
```

`Lock()` waits for all R's to drain. Your goroutine holds an R and is waiting — it will never drain itself.

```go
mu.RLock()
mu.Lock()   // deadlock — waiting for yourself
```

---

**2. W → R (downgrade) — DEADLOCK**

```
W + RLock = DEADLOCK
```

`RLock()` blocks when a writer holds or is waiting. You are the writer, so you block on yourself.

```go
mu.Lock()
mu.RLock()  // deadlock — you are the W blocking yourself
```

---

**3. R + R (recursive, same goroutine, W waiting) — DEADLOCK**

```
R (by G1) + Lock (W waiting) + R (by G1 again) = DEADLOCK
```

G1 holds R. A writer calls `Lock()` and blocks, poisoning new `RLock()` calls. G1 calls `RLock()` again — it blocks. G1 now waits for the writer, writer waits for G1's first R. Neither moves.

```go
mu.RLock()
// somewhere, another goroutine calls mu.Lock()
mu.RLock()  // deadlock
```

---

**4. Copy after use — SILENT BUG**

```
mu2 := mu1   // after any method was called on mu1
```

The copied mutex has no coordination with the original. Both think they own their state. This is not a panic — it's silently wrong. `go vet` catches it.

---

**5. Unlock without Lock / RUnlock without RLock — PANIC**

```
0 + Unlock  = panic
0 + RUnlock = panic
```

---

### The One Closure Rule

Every acquired lock must be released by the **same goroutine** that acquired it:

```
G1: RLock → ... → G1: RUnlock    ✓
G1: Lock  → ... → G1: Unlock     ✓
G1: RLock → ... → G2: RUnlock    ✗  (undefined behavior)
```

`defer` enforces this naturally:

```go
mu.RLock()
defer mu.RUnlock()

mu.Lock()
defer mu.Unlock()
```

---

### Summary Table

| Operation | Valid when | Produces | Blocked when |
|---|---|---|---|
| `RLock` | `0` or `nR` | `(n+1)R` | `W` held or `W` waiting |
| `RUnlock` | you hold `R` | `(n-1)R` | — |
| `Lock` | `0` | `W` | any `R` or `W` held |
| `Unlock` | you hold `W` | `0` | — |
| `TryRLock` | any | `R` or nothing | never blocks |
| `TryLock` | any | `W` or nothing | never blocks |

R (held by same goroutine) + Lock (by same goroutine) = DEADLOCK
nR (held by other goroutines) + Lock = BLOCKS, eventually resolves
